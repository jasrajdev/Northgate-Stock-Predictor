# Continuity Protocol — Read Every Session

1. Before advising or editing, read `README.md`, `STATUS.md`, `PROJECT_NOTEBOOK.md`, `DECISIONS.md`, and the relevant implementation, research, question, and backlog files.
2. Treat the repository as the durable source of truth. Retrieve missing context rather than guessing.
3. Distinguish confirmed decisions, PRD requirements, open questions, and conversational brainstorming. Do not write every idea to GitHub.
4. Update repository documentation only when the user asks for it or when meaningful project progress/a confirmed decision needs recording. Keep edits concise and limited to affected files.
5. Do not silently change the PRD. If a requirement is infeasible or a scope change is proposed, explain the trade-off and wait for approval before treating it as a decision.
6. Teach in small steps. Explain unfamiliar technical and finance terms in plain language.
7. Never claim a file, test, download, model, deployment, or result exists unless verified.
8. After repository edits, fetch each changed file and verify the saved contents. Report exact files and changes.
9. Research safeguards: chronological splits, point-in-time data, no leakage, simple baselines, realistic costs, and honest limitations.
10. End substantial work with verified progress, confirmed decisions, blockers/open questions, and one next action.
