# Northgate Model Training Guide

Updated: 2026-11-13

This is the handoff guide for the HP Victus training machine. Follow it together with [GPU_LAPTOP_SETUP.md](GPU_LAPTOP_SETUP.md), which contains the full Windows commands and hardware-specific setup.

## 1. Read these repository files

Read in this order:

1. `README.md` — project purpose and navigation.
2. `STATUS.md` — what has actually been completed and what is pending.
3. `PROJECT_NOTEBOOK.md` — project context and research safeguards.
4. `DECISIONS.md` — confirmed target and chronological split decisions.
5. `docs/PRD_REQUIREMENTS.md` — required models, metrics and final deliverables.
6. `docs/GPU_LAPTOP_SETUP.md` — exact Victus setup and run commands.

You do **not** need a PDF to run training. The model scripts consume CSV datasets generated by the repository. The original PRD is the requirements reference, not a training input; its concise traceable summary is in `docs/PRD_REQUIREMENTS.md`. Do not feed random research PDFs or the PRD PDF into the model.

## 2. Platform and tools

Use:
- **Windows PowerShell** for commands.
- **VS Code** to open the cloned repository and inspect scripts/reports.
- **Git + GitHub** to obtain the latest code and preserve source changes.
- **Python 3.11** in a project-local `.venv`.
- **PyTorch with CUDA 12.6 wheel** for the LSTM/GRU/BiLSTM/Transformer runs on the RTX 3050.
- scikit-learn and XGBoost for classical models.

The repository's last hardware record for the Victus is an NVIDIA RTX 3050 Laptop GPU with 4 GiB VRAM. Keep the initial deep-learning settings conservative. The CUDA runtime is supplied by the PyTorch wheel; the NVIDIA driver is required, but a separate full CUDA Toolkit installation is not part of the normal pip setup.

## 3. What the model learns from

The first experiment is deliberately **price/volume-only**:
- 10 provisional Indian equities plus `^NSEI` as a market benchmark.
- Daily OHLCV and adjusted close, rebuilt from Yahoo Finance.
- 24 backward-looking technical/price-volume features.
- Target: the same instrument's next observed trading session adjusted close; next-session log return and direction are retained as related labels.
- The benchmark is retained in the dataset for context but excluded from per-stock model fitting.

The script `scripts/prepare_gpu_training_data.py` rebuilds this dataset on the Victus. Market CSVs are not committed to GitHub; they are generated locally.

This is a **first baseline experiment**, not the complete PRD dataset. Macro releases, India VIX, RBI/PLFS, timestamped news, sentiment, and point-in-time index membership are still incomplete.

## 4. How the experiment is split

Rows are partitioned using the date the target outcome becomes known:
- Train: target dates through 2023-12-31.
- Validation: after 2023-12-31 and before the final six-calendar-month test window.
- Test: the final six calendar months of labelled observations.

Use training data to fit. Use validation data for early stopping and model selection. The final test partition is sealed: do not inspect it, tune on it, or use it to choose features/models. Only evaluate it once the model/feature decisions are frozen.

Every learned imputer/scaler must be fitted on training rows only. Never pass any `target_*` column into model inputs. Keep each ticker's rows in chronological order when building sequences.

## 5. Training order

### Step A — Prepare and quality-check the data

Run:

```powershell
python scripts/prepare_gpu_training_data.py
```

Inspect `reports/data_quality/gpu_data_build_report.json`. Stop if duplicate keys, invalid target chronology, missing target labels, or split assignment checks fail.

### Step B — Classical models and naive baseline

Run:

```powershell
python scripts/train_baseline_models.py
```

This compares:
- Naive last-adjusted-close baseline
- Ridge Regression
- Random Forest
- SVR (RBF)
- XGBoost

Ridge, Random Forest and SVR run on CPU. XGBoost attempts CUDA and has a CPU fallback. Results are validation-only.

### Step C — Deep-learning models

Only after data preparation and the classical run complete, run:

```powershell
python scripts/train_deep_models.py
```

This trains:
- LSTM
- GRU
- BiLSTM
- Transformer

The default settings are intentionally small for 4 GiB VRAM: sequence length 30, batch size 16, hidden size 32, one recurrent/encoder layer, up to 30 epochs, early stopping, and mixed precision on CUDA. If out-of-memory occurs, use the reduced settings in `GPU_LAPTOP_SETUP.md`.

## 6. What gets saved

Expected local outputs:
- `reports/data_quality/gpu_data_build_report.json`
- `reports/validation/model_comparison_validation.csv`
- `reports/validation/model_summary_validation.csv`
- `reports/validation/model_training_report.json`
- `reports/validation/deep_model_comparison_validation.csv`
- `reports/validation/deep_training_history.json`
- `reports/validation/deep_training_report.json`
- `models/deep/*_best.pt` model checkpoints

Keep data and model checkpoints on the Victus or a secure backup. Do not commit large datasets/checkpoints to GitHub. Send the JSON/CSV reports and the CUDA verification output back for review.

## 7. Metrics and interpretation

The scripts report MAE, RMSE, MAPE, R² and directional accuracy. Compare each model with the naive baseline on the same validation dates. Lower MAE/RMSE/MAPE is better; higher R²/directional accuracy is better, but none alone proves profitability.

The classical script's MAE/RMSE/MAPE/R² are computed on adjusted-close levels; the deep script predicts log returns and converts them back into adjusted-close predictions for price metrics. Directional accuracy is measured relative to the current adjusted close (classical) or from predicted/actual log-return signs (deep). Review these definitions before comparing numbers.

Validation results are for model selection only. They are not final out-of-sample evidence. A model can be retained only if it beats the random-walk baseline under the agreed held-out test evaluation, including the PRD's MAE and directional-accuracy requirements.

## 8. Important limitations and next work

This first run does not complete the PRD. Still required: macro/market-context and news/sentiment data, point-in-time availability alignment, full EDA/ADF and finance-math verification, portfolio optimisation/backtesting, recommendation rules, dashboard and report. The 10-stock universe is provisional and may contain survivorship bias.

Do not interpret a low validation error as an investment signal or promise of profit. Forecasting, recommendations and portfolio performance must be evaluated separately.
